# RTC 交互式网页 Slides 策划文档

## 目标

将 `deep-research-report.md` 中的 RTC 教学内容重组为可投屏、可互动、可逐步扩展的网页 slides。当前阶段已覆盖“导言 + 基础理论 + 协议与建连 + 架构 + 编解码与媒体处理 + 传输控制与性能优化 + 安全、部署与运维 + 代码与工程实践 + 行业与前沿”，重点让学生先建立 RTC 的概念边界、链路/指标判断语言，再理解协议协作、媒体架构、编解码策略、传输控制、线上治理、代码实验与产业趋势如何共同服务实时体验。

## 内容原则

- 每页只讲一个主命题，屏幕文字控制在课堂可读范围内，细节放到可交互卡片和讲者备注。
- 导言部分先讲“为什么”和“用在哪里”，避免学生一开始陷入协议名词。
- 基础理论部分强调可观测性：每个概念都尽量落到 Stats、用户体验或诊断动作。
- 编解码部分强调场景化取舍：不是记住“哪个编码最好”，而是判断互通、画质、功耗、时延和分层架构之间的约束。
- 传输控制部分强调数据流向：正向媒体流、反向反馈流、端侧控制流要同时展示，每个优化动作都必须落到链路中的具体位置。
- 安全运维部分强调线上治理：安全边界、部署路径、测试证据、监控公式、SLO 和故障复盘要能互相扣住。
- 代码实践部分强调可运行、可观测、可复盘：每段代码都必须落到消息方向、媒体路径或 Stats 证据。
- 行业前沿部分强调选型判断：标准、开源生态、托管云和 AI RTC 趋势都要回到课程中的时延、体验、部署和安全约束。
- 互动页不只是问答装饰，必须让学生先做判断，再用课程概念解释为什么。
- 外部示例图统一放在 `public/reference-figures/`，用 `referenceFigure` 图组组件承载；每张图只保留 2-3 个课堂观察点，避免把原始白皮书/工程图直接堆进画面。

## 交互与键盘

- `ArrowRight` / `Space` / `PageDown`：下一页。
- `ArrowLeft` / `PageUp`：上一页。
- `ArrowDown`：推进当前页互动；在课堂问答页中表示切换到下一个选项。
- `Enter`：激活当前页互动；在课堂问答页中表示揭示当前选项的参考判断。
- `ArrowUp`：回退当前页互动；在课堂问答页中表示切换到上一个选项。
- 数字键支持跳页，连续输入两位可跳到第 10 页及以后。
- `T`：切换深色/浅色主题。
- `N`：显示或隐藏讲者备注。
